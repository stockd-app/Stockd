# Frontend Docker Setup

## Overview

The frontend is built with **React + TypeScript** and containerized using **Docker**, with **Nginx** serving the production build.

This setup allows the frontend to:
- serve the built React application through Nginx
- connect to the backend through proxied `/api/*` requests
- keep production testing consistent across different machines

## Quick Start

### 1. Build the React app
```bash
# Install all frontend dependencies
npm install

# Generate the production build into the dist/ folder
npm run build
```

### 2. Start the container
```bash
# Make the shell scripts executable
chmod +x start.sh stop.sh

# Start the frontend Docker container
./start.sh
```

### 3. Access the app
Open browser: **http://localhost**

## How It Works

1. **Dockerfile** - Creates an Nginx container with your React app
2. **nginx-docker.conf** - Configures Nginx to:
   - Serve your React static files
   - Proxy `/api/*` requests to backend container
   - Strip `/api` prefix before forwarding (backend routes don't include `/api`)
   - Handle React Router (SPA routing)
3. **docker-compose.yml** - Manages the container lifecycle

## App Behaviour

### Routing and Protected Pages

The application uses **React Router** for navigation.

In `App.tsx`, protected routes check whether a user exists in `localStorage`. If no user is found:
- users are redirected back to the landing page
- authenticated pages such as dashboard, pantry, profile, saved recipes, and grocery list remain protected

This helps ensure that only logged-in users can access core application features.

### Theme Persistence

Theme choice is persisted using `localStorage`, meaning:
- returning users keep their previously selected theme
- first-time users automatically start with the browser or system preferred theme
- the selected theme is applied using `document.body.dataset.theme`

This allows the application to maintain a consistent appearance across sessions.

### Font Size Persistence

Text size preferences are also stored in `localStorage`, allowing the app to restore accessibility settings on future visits.

The saved value is mapped to a text scale and applied through a CSS variable, helping users keep their preferred reading size throughout the application.

### Navigation Layout

When a user is logged in:
- the `TopNavBar` is shown
- the `BottomNavBar` is shown
- the `body` gets a helper class for layout adjustments

This creates a more app-like and consistent navigation experience for authenticated users.

## Connecting with Backend

The nginx config proxies API requests to the backend container:

```nginx
location /api/ {
    rewrite ^/api/(.*) /$1 break;  # Strips /api prefix
    proxy_pass http://backend:8000;
}
```

**Example:**
- Frontend calls: `http://localhost/api/auth/google`
- Nginx forwards to: `http://backend:8000/auth/google`

**Important:** Both containers must be on the same Docker network (`stockd-network`)

## Configuration

### Change Port
If port 80 is busy, edit `docker-compose.yml`:
```yaml
ports:
  - "8080:80"  # Changed from "80:80"
```
Then access: http://localhost:8080

### Backend Connection
Make sure backend container is running:
```bash
cd ../Backend
./start.sh
```

Both containers must use the same network name in their `docker-compose.yml`:
```yaml
networks:
  stockd-network:
    driver: bridge
    name: stockd-network
```

## Troubleshooting

### Container won't start
```bash
# Check logs
docker-compose logs frontend

# Check if port is in use
lsof -i :80

# Remove and recreate
docker-compose down
docker-compose up -d
```

### Changes not showing
```bash
# Rebuild React app
npm run build

# Restart container
docker-compose restart frontend

# Hard refresh browser (Cmd+Shift+R)
```
Then access: http://localhost:8080

### API calls failing (404)
- Make sure backend container is running: `docker ps | grep stockd-backend`
- Check both containers are on same network: `docker network inspect stockd-network`
- Check nginx logs: `docker-compose logs frontend`

### API calls failing (500)
- This is a backend error, not nginx/docker
- Check backend logs: `cd ../Backend && docker-compose logs backend`
- Check backend environment variables in `.env`

### Google login issues

If Google login is not working:
- make sure the backend Google OAuth configuration is correct
- verify the frontend is calling the correct authentication endpoint
- check the redirect URI settings in the Google developer configuration
- inspect both frontend and backend logs for authentication-related errors

This is especially important because Google sign-in depends on both frontend routing and backend OAuth configuration matching correctly.

### Theme or text size not applying

If theme or font size changes do not appear:
- check that `localStorage` values are being saved correctly
- confirm `variable.css` and any related CSS variables are loaded
- make sure the app is applying `data-theme` and `--text-scale` correctly

These settings depend on both stored browser values and correct CSS variable usage across the app.

## Notes

- The `dist` folder is mounted as a volume, so rebuilding React updates the container automatically
- No need to rebuild the Docker image for frontend code changes
- Just run `npm run build` and restart the container
- Backend must be running for API calls to work
